# PRD-0034 / slice 34.1 — Bootstrap Miss Audit

Pure measurement output. Runs the regex bootstrap (`src/bootstrap/proposals.ts`)
against twenty hand-authored chunks in `tests/fixtures/bootstrap-miss-audit.yaml`
and classifies each result against a ground-truth label. Generated by
`src/eval/prd-0034-bootstrap-miss-audit.ts`.

## Methodology

Each chunk in the fixture carries a `ground_truth` field — what a human
reviewer would mark as the ideal bootstrap output:

- `candidate` — a candidate card is worth authoring
- `clarification` — the rule is ambiguous; a clarification need is the right shape
- `nothing` — no card or clarification is worth surfacing

The audit runs `generateBootstrapProposals` on the chunk in isolation and
compares the regex output to the ground truth. Classifications:

- `hit` — regex output matched (or exceeded) the ground truth
- `missed_candidate` — ground truth = candidate, regex produced nothing
- `missed_clarification` — ground truth = clarification, regex produced nothing
- `hedged` — ground truth = candidate, regex produced only a clarification
- `spurious` — ground truth = nothing, regex produced output anyway

**Empty-anchor assumption.** The audit calls `getConfidentSymbolAnchors`
with an empty list, modelling the first-bootstrap-on-a-fresh-import case
where no cards have been accepted yet and no confident symbol anchors
exist. This is the scenario PRD-0034's hypothesis targets — the high-
friction onboarding moment when the setup arc loses momentum.

## Per-chunk rationale

- **op-001** (missed_candidate) — The 90-day rotation cycle is a real operational constraint a new engineer would benefit from knowing — but the chunk uses none of the regex's normative words.
- **op-002** (hit) — "Always" pattern catches this — regex hit.
- **op-003** (hit) — The "should" word is regex-caught as a clarification. Ground truth agrees because the policy is ambiguous between team norm and hard rule.
- **op-004** (missed_candidate) — A concrete invariant (timeouts of 30s) stated as fact, not norm. Regex sees no signal.
- **op-005** (hit) — Pure narrative of behavior with no constraint embedded. A reviewer would not author a card from this.
- **arch-001** (missed_candidate) — "Coordinates" hint pattern is present, but no symbol anchor — so the symbol_note regex does not fire. A reviewer would still mark this as a symbol_note candidate worth authoring.
- **arch-002** (missed_candidate) — Architectural responsibility chunk with no normative word — the kind of thing only an LLM would catch.
- **arch-003** (hit) — Ambiguous: this could be a deliberate architectural rule or just a historical accident. A clarification needs to ask the maintainer.
- **arch-004** (hit) — Describes a name and a structure; no constraint, no leverage. Not worth authoring a card from.
- **dec-001** (missed_candidate) — A real constraint phrased as the rationale for a design choice. No normative word; regex sees nothing.
- **dec-002** (hit) — "Cannot" is caught as a strong rule — regex hit.
- **dec-003** (missed_clarification) — Reads as a historical decision but the constraint status is unclear — is this still policy, or just what happened?
- **dec-004** (missed_candidate) — A strong operational rule — "every outbound call enforces an idempotency key" — is buried inside the rationale prose. None of the regex normative words appear; the rule lives in the verb "enforces" plus the consequence narrative. Regex produces nothing.
- **param-001** (missed_candidate) — A factual bound (max 10MB) presented as a constraint, but with no normative word.
- **param-002** (hit) — Parameter docs that include the "must" rule do get caught — regex hit.
- **param-003** (missed_clarification) — Ambiguous-default behavior worth surfacing as a clarification — "what counts as production"?
- **mix-001** (missed_candidate) — Buried operational rule (sealed once finalized) in a chunk of mostly narrative. No regex signal.
- **mix-002** (hit) — Sentence mixes a "do not" caught by regex with surrounding context that complicates the rule. The clarification is the right shape.
- **mix-003** (hit) — Marketing-flavored prose. Nothing in here a reviewer would capture as a card.
- **mix-004** (hedged) — Mixed example with one normative word ("should") buried in a bigger architectural claim. Regex hits, but as a clarification — a reviewer would author this as a candidate (hedged).

The miss set is large enough and structurally varied enough that an LLM
augmentation lever is worth building. Slice 34.2 (THO-254) implements the
augmentation module behind a default-off `--llm` flag; slice 34.3 (THO-255)

authority boundary holds: every LLM output goes through the same human-
