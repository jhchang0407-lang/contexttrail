# PRD-0031 / slice 31.1 — Reverse-Import Miss-Shape Audit

Pure measurement output. Classifies the residual misses of the workflow-assembly and
agent-completion probes by graph shape. Generated by `src/eval/prd-0031-miss-shape-audit.ts`.

Predicate `target_imports_surfaced_seed` is load-bearing: only when true can
reverse-from-seed reach the target. Workflow doc misses are recorded as n/a — reverse-import
traversal is a code-graph lever and cannot help a docs-only miss.

## Methodology

**Agent-completion misses.** For each agent-completion case (14 tickets), the audit
enumerates the src files in the commit diff, then splits them into:
- Targets that exist in today's code-source index. The pack is assembled via
  `assembleContextPackWithLinks` (traversal-on default), and any src target not
  mentioned in any ranked body is recorded as a miss. The classifier then computes
  the graph-shape fields against the live import graph.
- Targets that do **not** exist in today's code-source index (rolled-back files).
  These are recorded directly as misses without running the pack — they are
  structurally unrecoverable by any retrieval lever, so all graph-shape fields are
  `n/a` and `proceed_eligible` is `no`.

**Workflow doc misses.** `runRealWorkflowEval` is run once; any unserved ticket's
missing primary doc(s) and the first member of each missing support group are
recorded. Reverse-import is a code-graph lever, so workflow doc misses are recorded
with `n/a` graph-shape fields. A doc that is also missing from disk is flagged as a
rolled-back-doc shape in its rationale.

**Determinism.** The set of rolled-back targets is structurally determined (commit
diff ∩ corpus = ∅), independent of FTS5 ranking. The classifier and seed-set
computation are pure functions of the corpus. Re-running the audit on the same
commit produces an identical row set.
